# myJobLauncher

登録しておいたコマンドを画面のボタンから実行できる、社内向けの汎用ランチャーアプリです。
定型作業（バッチ処理・ファイル操作など）をボタン化し、コマンドを覚えていなくても安全に実行できるようにします。

## できること

- 「ホーム」タブで、お知らせメッセージ・ホーム本文をMarkdownとして表示（緊急のお知らせは起動時にポップアップ通知）
- 登録済みジョブをボタンひとつで実行（同期／非同期）、実行結果・出力ログの確認
- ジョブは「定型」「非定型」の種別を持ち、非定型ジョブは業務記録プラグイン（ストップウォッチ）で作業時間を計測して実行履歴へ記録
- ジョブに「Tier」（業務の階層。Tier1〜8は全体共有、Tier9は個人専用、名称はカスタマイズ可）を設定して分類できる
- ジョブの複数選択（一覧左端のチェックボックス）による、すぐに実行／時刻を指定して実行
- 実行中・実行予定・完了などをステータス絵文字と強調色（実行中）で一覧表示
- 過去の実行実績から「日次／週次／月次／その他」を自動判定した一覧表示（列ごとにソート可能）
- ジョブごとに業務マニュアル（手順書のURL・フォルダ・ファイル）をワンクリックで開ける
- ジョブ単位の実行履歴（月別・日別集計、個別の開始〜終了時刻・経過時間をミリ秒単位で表示）
- よく使うツール（アプリ起動コマンド。作業ディレクトリ・引数の指定、Windowsキー操作にも対応）、よく使うリンク（URL・フォルダ・ファイル）の登録・起動。どちらもアイコン表示（大/中/小）・一覧表示を切り替え可能で、使用回数/名前/最終実行日時で並び替えできる
- Obsidian Vault（または任意のフォルダ）へ、個人単位・日付単位で「本日の作業実績／明日の作業予定／TODO／相談事項／連絡事項」を出力する日報機能
- 日付をまたいで持ち越せる個人用TODOリスト（完了時にObsidianノートまたはExcelファイルへ記録）
- Markdown/Mermaidドキュメントを見られるヘルプ
- 各種APIキー（Redmine等）を暗号化して保存する設定画面
- 画面テーマの切り替え（シンプルモダンのダーク／ライト／システム追従、モノトーン）
- 設定ファイルを共有フォルダのマスターとダウンロード／アップロードで同期
- OneDrive / SharePoint 等との連携（graph/flow方式は開発中。local方式は利用可）

## 必要な環境

- Windows
- Python 3.12 以上
- パッケージ管理ツール [uv](https://docs.astral.sh/uv/)

## セットアップ

```powershell
uv sync
```

## 起動方法

ブラウザで起動する場合（`--web`、既定なので省略可。既定ポートは8550）:

```powershell
uv run mj
```

```powershell
uv run mj --web --port 8550
```

デスクトップアプリ（ネイティブウィンドウ）として起動する場合:

```powershell
uv run mj --gui
```

ターミナル（TUI、Fletを使わないモード）で起動する場合:

```powershell
uv run mj --tui
```

（`uv run python main.py` でも同様に起動できます）

起動時にメニュー項目一覧などのデバッグ情報をコンソールへ出力したい場合は `--verbose` を追加してください（既定では出力しません）:

```powershell
uv run mj --verbose
```

### ターミナル（TUI）モードについて

**`--tui` は試験実装（experimental）です。** cursesベースのターミナルUIで、**「実行」と「履歴確認」のみ**をサポートします。
ジョブの追加・編集、ツール/リンク/日報/テーマ/Tier等の設定はGUI（`--gui`）またはWeb（`--web`）版で行ってください。
端末（フォント・幅・エミュレータ）によっては表示が崩れる場合があります。
**tmux・wtmux等のターミナルマルチプレクサ内での実行は動作保証外です。** `--tui`はWindows用の`curses`実装（`windows-curses`/PDCurses）がWindowsコンソールAPIを直接操作するため、マルチプレクサが提供する仮想的な画面バッファ越しでは座標計算が崩れることがあります。コマンドプロンプト・PowerShell・Windows Terminal等のネイティブなコンソール上で直接実行してください。

- ↑/↓ または j/k でジョブを選択、Enter または r で実行、h で履歴確認、q で終了
- 実行中は s キーで停止できます（{パラメータ}を含むジョブは実行前に入力を求められます）
- スペースキーで複数のジョブをトグル選択できます（`[x]`表示）。1件以上選択した状態で Enter/r を押すと、選択したジョブをまとめて実行します（非定型ジョブ・{パラメータ}が必要なジョブは一括実行の対象外。個別に実行してください）。一括実行後は選択が解除されます
- サブプロセスの出力等でターミナル画面が乱れた場合も、操作のたびに自動で全画面を再描画します（無操作中も一定間隔で再描画します）
- 初回のみ `windows-curses` パッケージのインストールが必要です（`uv sync` で自動的に入ります）

| 設定 | ジョブの追加・編集・削除、タイムゾーン・テーマ・Tier設定、ストレージ設定、設定ファイルの共有マスターとの同期、APIキーの登録 |

「日次」「週次」「月次」「その他」のセルにマウスを重ねると、直近の実行日（最新10件）がツールチップで確認できます。

## ホーム

アプリ起動時に最初に表示される画面です。「お知らせメッセージ」と「よく使うサービス」（ホーム本文）をMarkdownとして画面内にそのまま表示します。
本文中のリンクをクリックすると既定のブラウザで開きます。リンクにマウスを乗せている間は、そのMarkdownブロックの
直下にリンク先URLが表示されます（`utils/markdown_render.py`の自前レンダラーによる表示。表〈GFMテーブル、セル内改行は`<br>`〉は
対応済み、打消し線・タスクリストは非対応）。MermaidJSの図表は画面内には表示できないため、
含まれている場合は「図をブラウザで表示」ボタンから確認してください（ブラウザでの表示にはインターネット接続が必要です）。

- ホームタブを開くたびに、共有フォルダのホーム定義（お知らせ・ホーム本文）に新しいバージョンが無いか自動で確認し、あればダウンロードしてこのPCにキャッシュしてから表示します（確認・ダウンロード中は画面右上にスピナーが表示されます。オフライン時や失敗時は、このPCに保存済みの内容がそのまま表示されます）
- お知らせは公開日時が来たものだけが表示され、「通知期間」で指定した日数が過ぎると自動的に表示されなくなります
- 「緊急通知」に指定したお知らせは、公開日時が来た時点でアプリ起動時にポップアップ表示されます。複数件ある場合は1つのポップアップにまとめて表示されます。「お知らせ画面へ」を押すとポップアップを閉じてホームタブへ切り替わり、「キャンセル」を押すとポップアップだけを閉じます（どちらを押しても、同じお知らせが再度ポップアップされることはありません）
- お知らせメッセージ・ホーム本文は「設定」タブから追加・編集し、共有フォルダのホーム定義ファイル（`config/home.toml`）としてダウンロード／アップロードで同期できます（下記「お知らせ・ホームの管理」参照）
- 各お知らせは見出し部分をクリックすると折りたたみ／展開できます。「全て折りたたむ」「全て展開する」で一括切り替えも可能です（この開閉状態はアプリの再起動やタブの切り替えでは保持されません）
- お知らせ表示エリアの下端にあるハンドルをドラッグすると、表示エリアの高さを自由に調整できます。この高さはこのPCの設定（`config/app.toml`の`portal_notices_height`）として保存され、次回起動時にも引き継がれます（直接ファイルを編集して指定することもできます）
- ターミナル（`--tui`）版にはホーム機能はありません（「実行」「履歴確認」のみのスコープです）

## お知らせ・ホームの管理

「設定」タブの「お知らせメッセージ管理」から、お知らせの追加・編集・削除ができます。入力項目は「通知タイトル／公開日時（`YYYY-MM-DD HH:MM`、空欄なら即時公開）／通知期間（日数）／緊急通知フラグ／通知内容（Markdown/MermaidJS）」で、「プレビュー」ボタンを押すと保存前の表示イメージをその場で確認できます。

「ホーム定義」欄では、ホーム本文（Markdown/MermaidJS）を直接編集・保存・プレビューできます。

保存した内容は、このPC上のファイル（`config/home.toml`）に保存されるだけです。他のPCや共有フォルダへ反映するには、「ホーム定義をアップロード」を押してください（「マスターへアップロード」と同様、共有フォルダのホーム定義が他で更新されていれば警告します）。逆に共有フォルダの内容でこのPCを上書きしたい場合は「ホーム定義をダウンロード」を押してください。

## 複数ジョブの実行

実行タブの一覧左端「選択」列のチェックボックスにチェックを入れると、複数のジョブを選択できます。
2件以上選択すると「すぐに実行」（並行実行）と「時刻を指定して実行」（HH:MM形式で指定、過ぎていれば翌日）を選べます。
いずれも `{パラメータ名}` を含むジョブは対象外（個別に実行してください）です。
ステータス列には 🔵実行中 / ⏰予定 / ✅完了 / ❌失敗 / ⛔中断 が表示され、実行中のジョブ名は強調色（既定テーマでは青文字、モノトーンでは緑文字）になります。
モノトーンテーマでは、色付き絵文字の代わりに ●実行中 / ◇予定 / ○完了 / ×失敗 / △中断 の記号で表示されます（配色を緑と黒だけに統一するため）。

## ジョブの追加・編集

「設定」タブの「ジョブを追加」／ジョブ一覧の鉛筆アイコン、または実行タブのジョブ名を**右クリック**→「ジョブ情報の編集」から、画面操作だけで追加・編集・削除できます。
実体は [config/menu.toml](config/menu.toml) に保存されます（直接編集も可能です）。
入力欄は「ジョブ名／種別／Tier／カテゴリ／コマンド／非同期実行／スケジュール／業務マニュアル／作成日／最終更新日／成熟度／特記事項」の順で並びます（作成日・最終更新日は自動設定され、編集はできません）。
コマンド／業務マニュアル／特記事項は他の項目の2倍幅・3行分の高さの入力欄で、3行を超える内容は自動でスクロールします。成熟度は下から1、上に行くほど5になる並びで選択できます。

```toml
[[menu]]
name = "表示名"
command = "実行したいコマンド {パラメータ名}"  # job_type="非定型"の場合のみ省略可。それ以外は必須
async = false           # true にすると非同期実行（結果を待たずに次の操作が可能）
schedule = "0 9 * * *"  # 省略可。cron形式（分 時 日 月 曜日）で自動実行時刻を指定
manual = "\\\\shared\\manuals\\job.pdf"  # 省略可。業務マニュアルのURLまたはフォルダ/ファイルのパス
category = "分類名"     # 省略可。実行タブの「カテゴリ」欄に表示
job_type = "定型"       # 省略可。"定型"（既定）または"非定型"
tier = "戦略"           # 省略可。「設定」タブで定義したTierの名称（実行タブの「Tier」欄に表示）
enabled = true          # 省略可。falseにするとそのジョブは実行できなくなる（無効化）
created_at = "2026-01-01"  # 省略可。作成日（自動設定）
updated_at = "2026-01-01"  # 省略可。最終更新日（自動設定）
maturity = 3            # 省略可。成熟度（1〜5）
note = "備考"           # 省略可。実行タブの「特記事項」欄に表示
```

「ジョブID」（例: J001）は追加時に自動採番され、並び替えや削除をしても変わらない管理番号です。

`{パラメータ名}` と書いた部分は、実行時に入力ダイアログで値を指定できます。

## 実行タブの右クリックメニュー

実行タブのジョブ名を右クリックすると、以下の操作を選べるメニューが開きます。

- **表示位置の変更**: 一覧の「No.」の並び順を、選んだジョブを1つずつ上下に動かして変更します（他の項目は変わりません）
- **ジョブ情報の編集** / **業務マニュアルの編集**: どちらもジョブ編集ダイアログを開きます（後者は業務マニュアル欄にカーソルが移動した状態で開きます）
- **ジョブの無効化 / 有効化**: 無効化すると、そのジョブは（GUI・TUIどちらでも）実行・一括実行・スケジュール実行のいずれもできなくなります。一覧では「（無効化）」と表示されます
- **ジョブの削除**: 確認ダイアログで「削除」を押すと、そのジョブを削除します（元に戻せません）

## Tierによる業務の階層化

「設定」タブの「Tier設定」で、Tier1〜8（全体共有、共有マスターと同期される）とTier9（個人専用、このPCのみ）の名称を登録できます。
Tier1〜8は空欄のままにしておくと使いません。Tier9は必須（既定値「個人」）です。
ジョブの追加・編集ダイアログでは、登録済みのTierから1つを選択できます（未設定も可。Tier9→Tier1のような変更もここから行えます）。実行タブには「Tier」列（カテゴリ列の隣）が表示されます。
Tierとカテゴリは別軸として併用できます（Tierを設定してもカテゴリは置き換わりません）。

実行タブ右上の「Tierで絞り込み」から、特定のTierのジョブだけを表示できます（既定は「全体」）。ログタブの絞り込みは未対応です。

Tierの名称を後から変更すると、その名称を使っていた既存ジョブは表示上「未設定」扱いになります（ジョブ側は当時のTier名をそのまま保持しているため）。

## 非定型業務の記録

種別を「非定型」にしたジョブは、コマンドを実行する代わりに業務記録プラグイン（ストップウォッチ、`dev-stopwatch`）を起動し、作業時間を計測します。
「コマンド」欄は非定型ジョブでは使われないため、空欄のままで構いません。
起動先のHTMLファイルのパスは「設定」タブの「業務記録プラグインの起動先HTMLパス」欄で変更できます（`%USERPROFILE%`等のWindows環境変数を含められます。`file://`等のスキームは付けずに、素のファイルパスを入力してください）。

「設定」タブの「識別子（ユーザー名）」欄に、業務記録プラグインへ渡す識別子（ユーザー名）を登録しておいてください。

1. 実行タブで非定型ジョブを選び「実行」を押すと、業務記録プラグインが開き計測が始まる（「設定」タブで登録した識別子・選んだジョブ名が、業務記録プラグイン側の識別名(ユーザー名)/JOB欄に自動で入力され、COMMENT欄には固定で「ランチャー連携開始」が入力されます）
2. 作業が終わったら「完了として記録」を押すと、開始〜終了時刻が実行履歴へ記録される
3. 非定型ジョブは一括実行・スケジュール実行の対象外です（個別に実行してください）

## 設定ファイルの共有

複数人・複数PCで同じジョブ設定を使いたい場合、「設定」タブの「共有マスター設定ファイルのパス」にOneDriveやSharePoint等の共有フォルダ上のファイル名を指定すると、
「マスターをダウンロード」／「マスターへアップロード」で同期できます。

**ジョブは項目（1件ごと）単位で安全にマージされます。** 「ダウンロード」を押しても、まだ共有フォルダへ反映していないこのPCだけのジョブの追加・変更が消えることはありません（同様に「アップロード」を押しても、まだこのPCに取り込んでいない共有フォルダ側の追加・変更は消えません）。同じジョブが両方で異なる内容に変更されていた場合（真の衝突）だけ、このPCの内容を維持したうえで、対象ジョブ名を通知します（自動的な選択はしないため、その場合は内容を見て手動で調整してください）。ストレージ設定・Tier名（`[storage]`/`[sync]`/`[tiers]`）は従来通り「ダウンロード＝共有フォルダの値で上書き」「アップロード＝このPCの値で上書き」のファイル単位のままです。

- アプリの起動時にも、共有マスターの自動取り込みを試みます（未設定・失敗時はこのPCの設定をそのまま使うので、オフライン時等でも起動に問題はありません）。この自動取り込みも上記と同じ項目単位のマージです
- 自動取り込みは、まず共有側の更新日時とこのPCのファイルの更新日時を比較し、共有側が新しい場合のみ、さらに内容のハッシュ値を比較します。内容が実際に変わっていない場合は取り込みをスキップします
- ダウンロード・アップロードとも、ファイル共有への一時的なアクセス失敗（ネットワーク瞬断等）は自動的に再試行します
- ストレージ種別が `local` の場合の「ローカル保存先フォルダ」は、`%USERPROFILE%`や`%OneDriveCommercial%`等のWindows環境変数を含められます
- 同じストレージ設定を使って、お知らせ・ホーム本文（`config/home.toml`）も別ファイルとして共有できます。「共有ホーム定義ファイルのパス」にファイル名を指定してください（詳細は「お知らせ・ホームの管理」を参照）


## タイムゾーン

実行履歴・日報・スケジュール実行の日付/時刻は、既定で日本時間（Asia/Tokyo）を基準にします。
「設定」タブの「タイムゾーン」欄でIANAタイムゾーン名（例: `Asia/Tokyo`, `UTC`）を指定して変更できます。
スケジュール実行（cron）への反映にはアプリの再起動が必要です。

## テーマ

「設定」タブの「テーマ」欄から画面の配色を切り替えられます。保存すると即座に反映されます。

| テーマ | 内容 |
| --- | --- |
| シンプルモダン（ダーク） | 既定のテーマ。ダークモード |

## 困ったときは

- 実行ログ（標準出力・エラー）と、アプリ内部の動作ログは同じ形式で統一されており、アプリ画面（「ログ」タブ）のほか `logs/app-YYYYMMDD.log`（日付単位のファイル）にも保存されます。ログの書式・日時形式・出力先（画面／ファイル）は `config/log_format.toml` で変更できます（下記「運用ログの書式設定」参照）
- 「ログ」タブは起動時に当日分（`logs/app-YYYYMMDD.log`）の内容をまとめて表示します。アプリ起動後に出力された分だけでなく、その日の朝から今までの分をさかのぼって確認できます。マウスでドラッグすれば複数行にまたがる任意の範囲を選択してコピーできます（右上の「コピー」アイコンは表示中の全行をコピーします）
- 実行履歴は `app.db`（DuckDB ファイル）に保存されます
- 登録したAPIキーは、このPC・このWindowsユーザーでのみ復号できる形式で暗号化されます

## 運用ログの書式設定

「ログ」タブと `logs/app-YYYYMMDD.log` に出力されるログの書式は、既定で以下の形式です。

```
ID| 日時| 端末名| アプリケーション名| 機能名| 区分| メッセージ内容
```

- 先頭のID（ジョブ実行の識別子。ULID風の`uuid7`）はジョブ実行ログにのみ付き、アプリ内部の動作ログ等では空欄になります
- 日時は既定で `2026/09/22 11:23:34.821750`（`%Y/%m/%d %H:%M:%S.%f`、マイクロ秒6桁）形式
- 区分は `INFO`／`NORMAL`／`WARNING`／`ERROR` のいずれか
- 理由を伴うメッセージは「メッセージ内容 理由＝〇〇」の形で出力されます

これらは `config/log_format.toml`（未使用時は無し、既定値で動作）を作成・編集することでカスタマイズできます。専用の編集画面は無く、直接編集で指定します。

```toml
format = "{command_id}| {datetime}| {hostname}| {app_name}| {func}| {level}| {message}"
datetime_format = "%Y/%m/%d %H:%M:%S.%f"
destinations = ["file", "screen"]   # "file" と "screen" を任意の組み合わせで指定可
log_dir = "logs"
```
